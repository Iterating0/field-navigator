# Field Navigator 科研领域导航器

Field Navigator 帮助学生进入陌生科研领域：从一个明确的研究主题出发，找到前置知识、研究分支和可追溯的论文阅读起点。参赛公开材料使用中性项目名称，不包含参赛者个人信息、密钥、数据库或私人笔记。

## 解决的问题

文献检索通常返回平铺的论文列表，初学者仍需判断先学什么、哪些方向值得深入、推荐理由依据什么。Field Navigator把检索结果组织成可继续探索的领域图谱，并将领域关系连接到支持论文。

## 当前能力

- 输入明确的领域名称或研究问题，从 OpenAlex 获取候选论文。
- 大模型生成前置领域、研究分支与论文评价，结构化输出经过校验。
- 关系详情可展开支持论文的标题与链接，包括未进入核心论文列表的实际证据。
- 分阶段展示候选论文、领域地图和最终排序；可取消分析、继续探索分支、收藏论文和导出 JSON/研究简报。
- 本地 SQLite 缓存完整结果与已成功的分析阶段，失败不会覆盖已有完整结果；研究问题上下文与缓存键隔离。

输入简称或范围不清时仍需用户提供更明确的问题。排序是候选集中的启发式推荐，模型置信度未经概率校准。

## 证据质量链路

一次未命中完整缓存的真实 LLM 探索包含 5 个有界批次：检索规划、地图生成、论文评价、独立地图审查和核心论文审查。

1. 默认最多使用 3 条互补检索路径，每条最多 40 条记录；原始结果合计最多 120 条，去重合并后送入模型的候选池最多 40 篇。规划失败时保留 exact-topic 的基础引用检索 lane 作为确定性降级，不猜测同义词，也不因规划失败重试 LLM。
2. 地图和论文评价分别生成，输出只允许引用本轮候选论文；未知 ID 会被丢弃。
3. 独立地图审查逐条检查关系是否落在研究问题范围内；每条关系先核对 evidence provenance，再只用自己的实际 quote 做 scope gate。混合范围摘要会过滤被阻断的 quote 及因此失去有效 evidence ID 的项；如果整篇摘要的候选 quote 都被 scope 阻断，则删除 relation。生成与 audit 都显式区分 dimension、layer、species、task 四个 scope 维度。
4. 排序后的核心论文接受独立核心审查，判断推荐理由是否得到元数据支持，并返回 `direct`、`context`、`off_topic` 或 `insufficient` 等保守结论；`insufficient` 一律移出核心列表，题名重合不会推翻审查结论。
5. 无支撑关系会删除，弱证据会降级并带警告。只有 `direct` 且有可逐字核对的题名摘录时，才可作为明确标注的弱线索；综述最多保留 1 篇，核心列表可能少于 8 篇。`ML prediction` 只有同一句明确写出机制或因果语境时才触发理论标签。

摘录验证用于来源追溯，不等同全文引文核证或语义蕴含证明。地图审查只使用该关系自己已核对的摘录及题名上下文；核心审查也会对最终展示的 quote 再做 scope check，只使用该推荐自己的摘录与题名/ID上下文，并展示同一份完整摘录，理由只能描述该摘录覆盖的事实。如果自己的摘录明确冲突，不能引用全文另一段背景、旧理由或另一篇论文的摘要来补回一维、物种等范围。这里的独立审查是分开的模型生成/复核调用，不代表不同模型或人工专家。更保守的失败处理可能降低召回。不读取 PDF，也不调用全文 RAG。

检索后的来源核验由 `LiteratureRetriever` 和 `ArxivMetadataVerifier` 完成。候选中的 arXiv 标识先去掉版本号并按官方 Atom API 批量核验；一个批次中缺失的标识只使用一次按 exact DOI 的 DataCite 注册元数据查询作为 fallback，不重复请求同一接口。来源字段和摘要来源记录保留供追溯，并进入分析 payload；界面区分 arXiv 摘要与 DataCite 注册摘要；核验只处理题名、摘要、作者、年份和 DOI 等元数据，不抓取全文。索引身份与官方记录冲突时保留主 work ID，并在安全的预印本路径上清除不属于该身份的引用量和参考文献；跨版本合并也不继承引用量。DataCite 返回的不属于请求集合的 DOI 不会作为官方核验记录并入；未核验的原候选可能保留，预印本的摘要、引用量和参考文献信号会清除。

LLM 的 JSON transport 兼容层只处理完整 `json` fence，以及字符串内明确的 invalid escape、invalid Unicode escape 和 raw control character。auto 只在明确表示当前模型/服务不支持 `response_format` 或 `json_schema` 时回退到 `json_object`；鉴权、限流和 schema 内容错误不重试。缺引号/括号、尾随说明和多段 JSON 仍失败，Pydantic 业务 schema、证据 ID、逐字摘录和独立审查规则保持不变。

JSON-mode 的 raw presentation 预算与业务 schema 分开：模型每组最多返回 20 条关系、每条关系最多 8 条 evidence quote，以容纳有界的长列表；每条记录仍逐项校验 type、ID、confidence 和 quote 格式。canonical + dedup 后 public 保留 5/7，另有 3 条 quote 进入复审，系统不会自行补写证据。这是受限的展示容量配置，不是业务 schema 的泛化放宽。

生成和审查提示词要求将 `nodeless` 译为“无节点/全能隙”，不译成“无能隙”。[PRB 术语来源](https://journals.aps.org/prb/abstract/10.1103/PhysRevB.102.024523)只用于术语核对，不为任何 KTaO3 结论背书。当前 `quality_revision=10`、`PROMPT_VERSION=19`、`RETRIEVAL_VERSION=12` 纳入分析产物和缓存指纹，避免旧版本缓存复用。地图或分支的 `corrected_name` 会重新经过范围门，并把关系理由收窄到该关系自己的已核对摘录；同 kind 的更名碰撞只保留 `evidence_status` 或 `confidence` 更强的 relation，不拼接两条 relation 的 claims 或摘录。

模型审查前另有范围规则，过滤明确的一维、双层、哺乳动物问题中明显冲突的维度、层数和物种；比较研究、跨维映射、明确的跨物种问题以及有限的非哺乳动物 taxon 例外按规则保留。每条关系先做 provenance 核对，再做本条 quote 的 scope gate；核心最终 quote 也必须重新通过 scope check。对规则识别到的数值评测摘录，理由限定为所引论文的具体设置，不外推其他模型或任务。v13 的有限数值模式扩展覆盖 correlation、rank metric、分组计数以及 Unicode 百分号/范围表达，但仍要求摘录保留具体评测设置，不提供不受限的通用 NLP 语义能力。这些规则仍不能替代全文阅读或领域专家判断。来源核验后的收藏元数据修正会保留个人笔记与阅读状态，引用量不会从错配记录或其他版本继承。

## 演示方式

离线演示路径为 NHSE → Incoherent NHSE → Photonic quantum walks。离线模式不调用外部模型，界面明确标为预设演示。

真实分析须配置论文检索服务及兼容 Chat Completions 的模型服务；没有模型 key 时，非预设领域仅展示论文，不编造研究分支。实时模式会向检索服务发送研究问题，并向模型服务发送研究问题及候选论文元数据和摘要。

## 最小演示顺序

1. 用 NHSE 离线演示解释领域图谱、前置知识与研究分支。
2. 展开一条关系的支持论文，打开原始来源，说明证据状态和摘录边界。
3. 进入研究分支，返回已有结果，收藏一篇论文并导出 JSON。
4. 用一个明确研究问题做真实分析，展示论文来源、地图/核心审查标识和实时/演示模式区别。

仓库没有 PDF 解析、RAG 问答、自动学术审稿、自动综述或完整的简称澄清功能。参赛介绍只描述以上已实现能力，质量数字以[推荐质量说明](RECOMMENDATION_QUALITY.md)和实际验证记录为准。
